# MacRemote v0.5.1 Corrective Release Design

## Goal

Make the native Android replacement a safe in-place upgrade from v0.4.4 by restoring the established brand and closing every confirmed behavior-parity regression found after v0.5.0 shipped.

## Approach

Patch the native client rather than rolling back or rewriting it. The native Compose architecture and the server reliability fixes remain; compatibility behavior lost during the migration is restored behind focused regression tests.

## Branding

- Restore the canonical Command-loop and green play mark from the v0.4.4 source assets.
- Generate Android launcher resources from those existing assets without redrawing the mark.
- Keep one recognizable mark across adaptive, monochrome, and legacy launcher paths.
- Update repository-facing technology labels from React Native to native Kotlin/Compose where the migration made them stale.

## Behavior corrections

- Route main seek controls through the selected browser tab when browser media owns the transport.
- Persist activation when saving an edited inactive device so the foreground app, widget, media service, and next launch agree.
- Make legacy preference migration idempotent and preserve later native brightness choices.
- Retain the v0.4.4 widget provider component name so existing home-screen widgets survive the APK upgrade.
- Treat widget commands as best-effort and open setup when no device is configured.
- Decode fullscreen responses and surface server refusal notes.
- Prevent stale media-service status polls from replacing a newer local play/pause intent.
- Restore custom sleep-timer durations and editing of a running timer.
- Preserve older-extension tab control behavior when `controllable` is absent.
- Provide an upgrade-safe path for existing non-placeholder server tokens while continuing to reject empty and known placeholder tokens.

## Testing

- Add JVM tests for pure routing, migration, playback ordering, timer selection, and response decoding.
- Add manifest/resource regression checks for the legacy widget component and canonical launcher assets.
- Add server tests for token compatibility and placeholder rejection.
- Build both debug and release APKs, run Android lint and all unit tests, and inspect the signed APK manifest, version, digest, and signing certificate.
- Preserve package ID, minimum SDK, and signing identity so v0.5.1 installs over v0.4.4 and v0.5.0.
- Run the full server and extension suites plus CI/release workflows.

## Release

Ship v0.5.1 through the existing GitHub Release pipeline. Verify the downloadable APK independently, then confirm the Mac updater checks out the exact v0.5.1 tag and reports that version from the live service.
